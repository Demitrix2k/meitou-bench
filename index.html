Meitou daily benchmarks

Fixed benchmarks of Meitou, a C#/.NET Vulkan reimplementation of Kenshi, run after each upstream master update. Lower is better for every metric.

How to read these charts

Same stages and names as the F12 profiler. CPU is the render thread's time per stage (uploads, cull and bake have no CPU line); GPU is measured with timestamp queries (driver-wait has no GPU line; "other" is GPU time outside the stamped stages). The CPU and GPU lines are of the same frames but run in parallel, so they do not add up to the frame time. Values are per-stage distributions over the frames after the settle phase.

How this is measured

Setup

Fixed for every run, so numbers from different days are comparable.

Build
Native Linux build of upstream master
Game data
Clean, unmodded game data (GOG copy)
Save
The same frozen save every run: two player bases; never played or saved over
Graphics
Full settings
Measurement
MangoHud frame-time logging; frame metrics come from the game's bench frames
Machines
The maintainer's laptop and machines of contributors; see "Machines" below
Run by
The maintainer after each upstream master update; contributors with the dev kit in kit/

Scenarios

Two scenarios are run: the play benchmark is upstream's own --play-bench (camera segments idle, orbit, zoom, pan); the base switch jumps the camera four times between the two bases. "Slow-world tick" is the game's own timing of its slowest simulation ticks.

Runs and series

Each benchmark is run twice back-to-back. Run 1 may be cache-cold (disk cache, shader cache) and often looks worse; run 2 is the warm one. Runs are never averaged together; older single-run data counts as run 1. Within one commit and scenario, runs are numbered by time: run 1 is drawn as a filled circle, run 2 as a hollow diamond. The "Runs shown" control above the charts picks which are drawn.

    Series break lines on the charts mark where the procedure changed, so a jump across one may come from the procedure rather than from the code. Cache-cold run 1 in series 2 is the closest match to series 1's single runs.

    Off-target commits

    A benchmark target is a commit everyone is asked to run, so results can be compared. An off-target commit is one that is not a target (for example an older commit run later to fill in history). It is drawn faded in the charts, not connected by lines, and left out of comparisons between machines. The commit order everywhere is upstream's, not the order the runs were made in.
